# Архитектура версии 0.7

## Границы текущей версии

Монолит для самостоятельной проверки и закрытого пилота. Браузерный интерфейс на ES-модулях без сборки; сервер на Node.js, база SQLite через `node:sqlite`. Производственных npm-зависимостей нет. Единственная внешняя зависимость интерфейса — фиксированная версия Pyodide 0.27.7 с CDN, используемая только при запуске Python.

По умолчанию `GRAPH_MODE=local`: сервер слушает только `127.0.0.1`, а `START.cmd` сохраняет прежнее поведение. Режим `demo` подготовлен для HTTPS за доверенным прокси, с явно заданными адресами, базой и внешним паролем доступа. Для него есть Docker Compose комплект; наличие конфигурации не означает выполненное размещение. Локальное приложение поддерживает Node.js 22.13+, Docker и полный набор проверок резервных копий используют Node.js 24+.

## Модель → история → представление

`public/core.js` содержит граф, валидацию, список соседей, генераторы примеров, `trace()` и проверку маршрута. В нём нет DOM, хранилища или сети. `trace(graph, algorithm, start, target)` возвращает независимые снимки: текущая вершина, очередь, стек вызовов, завершённые вершины, порядок, расстояния, предшественники, активные рёбра, итоговый путь, счётчики и объяснения.

`public/app.js` хранит индекс истории и отображает выбранный снимок. Шаг назад не обращает алгоритм, а уменьшает индекс. BFS агрегирует обработку вершины в один шаг; DFS показывает вход, переход, пропуск открытого соседа и возврат; Дейкстра показывает выбор минимума и проверки рёбер.

`public/course.js` хранит 15 занятий, цели, текст, упражнения и шаблоны Python. Следующий этап — вынести содержание в отдельные файлы с версиями и методической редакцией. Тексты событий ядра также можно отделить от расчёта в форматтер.

## Языки в версии 0.3

`i18n.js` и `locales/ru.js`, `locales/kk.js` отделяют русские исходные тексты и казахский перевод от вычислений. Шаблон переводится до подстановки динамических значений: имена, код и комментарии пользователя остаются исходными. Материалы `course.js` копируются с локализованными текстами; идентификаторы и правильные ответы общие. Русские пояснения независимого ядра переводятся только при отображении. Серверная оценка и схема базы не менялись.

При смене языка интерфейс пересоздаётся с сохранением шага и полей ввода; камера 3D сбрасывается, проигрывание и запущенный Python останавливаются. Подробности и порядок редактирования — в `LOCALIZATION.md`.

## Данные базы

- `users`: логин, отображаемое имя, роль, соль и производное пароля.
- `sessions`: хэш случайного токена, CSRF-токен, срок действия.
- `classes`, `members`, `assignments`: классы, участие и назначения занятий.
- `attempts`: ответы и результат серверной проверки вопросов.
- `submissions`: последняя сохранённая Python-работа пользователя по занятию, пояснение и клиентский отчёт самопроверки.
- `feedback`: комментарий учителя к работе ученика своего класса.

В SQLite включены foreign keys, WAL и `busy_timeout=5000`. Запросы используют параметры. Удаление аккаунта каскадно удаляет связанные данные в соответствии со схемой. Обновление работы пока перезаписывает предыдущую отправленную версию; история отправок не реализована. Схема 0.7 совместима с 0.1–0.6; локальная база не переносится в Docker автоматически.

## Учётные записи и права

Пароли обрабатываются асинхронным scrypt с индивидуальной солью; дорогое вычисление не блокирует основной поток HTTP-сервера. После вычисления повторно проверяется конфликт логина перед созданием аккаунта. Сессия — случайный токен, в базе хранится его SHA-256; cookie `HttpOnly`, `SameSite=Strict`, `Path=/`, срок 7 дней. В локальном HTTP используется `graph_session` без `Secure`. В режиме demo — `__Host-graph_session` с `Secure` и без `Domain`, включая очистку cookie при выходе и удалении аккаунта. Просроченные сессии периодически удаляются.

Изменяющие запросы требуют ожидаемый Origin; авторизованные изменения также требуют CSRF-токен. Учитель видит только собственные классы; ученик — собственные результаты. Членство проверяется при работе с обратной связью. `server-security.mjs` ограничивает размер JSON до 64 КиБ и принимает только объект верхнего уровня; отдельно обрабатываются повреждённый JSON и прерванные запросы.

Ограничители попыток входа, регистрации и внешнего пароля хранятся в памяти одного процесса, очищают истёкшие записи и имеют ограничение числа записей. Они не являются распределённой защитой. По умолчанию адрес клиента берётся из сокета. Только в demo при `GRAPH_TRUST_PROXY=1` допускается валидный IP из `X-Graph-Client-IP`; комплектный Caddy всегда перезаписывает этот заголовок. Доверять ему при прямом доступе к Node.js нельзя. Проверки Host/Origin не зависят от этого заголовка.

Свободная регистрация с ролью учителя предназначена для самостоятельной проверки. Для школьного пилота требуются подтверждение учителей, управление приглашениями и отзывом доступа, восстановление паролей и журналирование важных действий.

## Python и границы доверия

Локально основной интерфейс обслуживается на 4318, среда выполнения — на отдельном origin 4319. В demo используются HTTPS-адреса **с разными именами хостов**: cookies не изолируются только портами. Их `APP_ORIGIN` и `RUNNER_ORIGIN` проверяются в `server-config.mjs`; пути и произвольные адреса из запросов не подставляются в конфигурацию. Runner отдаёт только разрешённые файлы среды и `runner-config.js` с ожидаемым origin родителя, не обслуживает API или файлы приложения. Обмен идёт через `postMessage` с проверкой origin, source и идентификатора запуска. CSP разделяет разрешённые ресурсы. Worker создаётся заново на каждую проверку и завершается после неё.

HTTP Basic защищает основное приложение и API в demo. Секрет читается из `DEMO_PASSWORD_FILE` (в Docker — отдельный файловый secret); одновременная передача пароля значением и файлом запрещена. Сравнение производится через дайджесты и `timingSafeEqual`. Runner не получает внешний пароль и не требует его для iframe. Индивидуальные аккаунты внутри платформы остаются отдельным уровнем авторизации.

Загрузка интерпретатора ограничена 90 секундами, выполнение — 8 секундами; ручная остановка завершает Worker. Это не полный контроль памяти браузера и не доказательство безопасности выполнения произвольного кода. Код пользователя изолирован от интерфейса приложения происхождением документа; браузер, конфигурация CSP и весь канал сообщений требуют отдельной проверки перед пилотом.

Python проверяется на 8 графах, DFS дополнительно проверяется на синтаксическое наличие рекурсивного вызова. Эта эвристика не доказывает, что фактический обход был реализован рекурсивно. Сложные ошибочные или намеренно обходящие проверку решения должен оценивать преподаватель.

Клиентский отчёт Python недоверенный. Сервер хранит его как самопроверку, не использует его для защищённой итоговой оценки. Для аттестации потребуется независимое серверное выполнение в ограниченной среде или иной утверждённый порядок проверки. Ученический Python нельзя запускать внутри основного API-процесса.

Подсветка подготовленного алгоритма в визуализации и выполнение произвольного ученического Python — отдельные механизмы. Трассировка произвольного кода с синхронной анимацией не реализована.

## Перед школьным пилотом

Нужны методическая редакция материалов, подтверждение официальной программы и критериев БЖБ; определение ответственного за данные, оснований обработки, сроков хранения и процессов удаления; проверка подготовленного размещения с настоящими DNS и HTTPS; независимый обзор авторизации и изоляции кода; тест восстановления на выбранном VPS, нагрузочная и доступностная проверка. Подход к обработке данных школьников необходимо согласовать со школой до использования реальных учётных записей.

Для министерского показа можно демонстрировать учебный сценарий с вымышленными данными локально или после проверки закрытого размещения. Поддержка государственной программы, официальное одобрение и доказанная учебная эффективность не заявляются.

## Размещение и эксплуатация, 0.7

`Dockerfile` создаёт образ Node.js 24 с явным перечнем исходников и отдельным target для тестов. `.dockerignore` исключает базу, секреты и лишние рабочие файлы из контекста. `compose.yaml` запускает один `app`, отдельный `backup` и `caddy`. У Node.js фиксирован UID/GID 1000, файловая система контейнера read-only, `/tmp` находится в tmpfs, права Linux ограничены; база и копии пишутся в отдельные постоянные тома. Логи ротируются.

Только Caddy публикует порты 80/443. Приложение находится во внутренней сети, `backup` не имеет сети. Caddy маршрутизирует два имени к внутренним портам 4318/4319, получает сертификаты и перезаписывает доверенный IP-заголовок. Сертификаты сохраняются в постоянном томе. Развёртывание подразумевает один VPS и один экземпляр приложения, без горизонтального масштабирования.

Настройки Compose берутся из `.env.hosting`, общий пароль — из `secrets/demo_password.txt`. Пароль не хранится в образе и значении environment. Исходному файлу Linux нужны владелец 1000:1000 и режим 0400. Конфигурация и секреты не входят в Git. `DB_FILENAME` задаёт один и тот же `/data/имя.sqlite` для приложения и копирования; это также механизм переключения на восстановленную базу.

`/healthz` проверяет доступность приложения и базы; в demo он находится за тем же внешним паролем. `scripts/healthcheck.mjs` обращается к приложению и проверяет конфигурацию runner без вывода секрета. Сервер обрабатывает SIGINT/SIGTERM: прекращает принимать запросы, закрывает оба HTTP-сервера и базу, ограничивая ожидание активных соединений. Контейнеры перезапускаются при завершении процесса; состояние unhealthy само по себе не является системой оповещений владельцу.

### Снимки и восстановление

`scripts/backup.mjs` требует Node.js 24+. Сначала проверяется существующий непустой файл источника, затем он открывается read-only: отсутствующая база не создаётся молча. `node:sqlite.backup` получает согласованный снимок вместе с подтверждёнными WAL-изменениями. Снимок создаётся в собственной временной папке, переводится в DELETE journal mode, проверяется через `quick_check` и наличие таблиц, синхронизируется на диск и публикуется через атомарный hard link без перезаписи. Временная папка находится на том же файловом томе. Проверка не подтверждает предметную корректность всех ученических данных и не заменяет проверку восстановления.

Только после успешной публикации удаляются старые файлы точного собственного шаблона `graph-classroom-ДАТА-UUID.sqlite`. По умолчанию остаются 14 снимков; новый снимок и исходная база сохраняются даже при переводе времени назад, поэтому в таком случае возможен дополнительный снимок. Чужие имена, каталоги и незавершённые файлы не участвуют в очистке.

`scripts/backup-loop.mjs` запускает первую копию сразу и далее последовательно через заданное число часов, без перекрытия собственных запусков. По SIGTERM текущая операция завершается, ожидание следующего запуска отменяется. Ошибка завершает процесс с ненулевым кодом. `backup-healthcheck.mjs` отслеживает отсутствие и возраст завершённых снимков. Копии остаются на том же VPS; загрузка во внешнее хранилище и оповещения администратору не реализованы.

`scripts/restore.mjs` восстанавливает только в новый путь и отклоняет существующий целевой файл, `-wal`, `-shm` или `-journal`. После проверки копии файл публикуется без замены прежней базы. Перед переключением нужно остановить `app` и `backup`, выставить новое `DB_FILENAME` и пересоздать сервисы. Старый файл сохраняется для возврата. Откат кода не является откатом схемы или данных; будущие миграции должны иметь отдельный проверенный план восстановления.

Практические команды приведены в [DEPLOYMENT.md](DEPLOYMENT.md). Автоматические тесты проверяют живую WAL-базу, целостность снимка, отказ без исходника, ограниченную очистку, восстановление и обработку конфигурации. GitHub Actions workflow подготовлен для Docker-проверок; выполненное CI, настоящие TLS-сертификаты и работа на VPS пока не подтверждены. Сводка — [TECH_REVIEW_V07.md](TECH_REVIEW_V07.md).

## Расширение

Следующие изменения естественно отделяются: назначение пользовательского графа; версии заданий и отправок; серверная проверка программ; восстановление доступа; методические материалы для учителя; сравнение обучения по согласованной методике. Их стоит добавлять по итогам проверки текущей версии, см. VERSIONS.md.

Опционально интерфейс регистрирует WebMCP-инструменты чтения прогресса и открытия занятия, если браузер поддерживает `document.modelContext`. В 0.2 оба инструмента проверены в браузере Codex: чтение вернуло 15 занятий, открытие перевело интерфейс на занятие 19. В обычном браузере приложение работает без WebMCP.

## Разделение 2D, 3D и модели в версии 0.2

`core.js` остаётся единственным источником шагов алгоритма. `app.js` передаёт один снимок в SVG-отрисовку 2D или в `Graph3D.update()`. При переключении вида `ui.index`, старт и цель сохраняются. Вращение не вызывает `trace()`.

`spatial.js` — чистые функции XYZ-раскладки, поворота, перспективной проекции и обратного преобразования для перетаскивания. Отдельный словарь позиций не меняет объекты `graph.nodes`. `graph3d.js` реализует взаимодействие и выводит эту модель в SVG; внешняя 3D-библиотека не используется. Painter's algorithm сортирует примитивы по глубине; это упрощённое отображение, не точный рендер пересечений объёмных объектов. При перекрытии подписей можно повернуть камеру или переключиться в 2D.

Перерисовка при движении объединяется через requestAnimationFrame. Постоянного цикла отрисовки нет. dispose() отменяет отложенный кадр и удаляет обработчики через AbortController. Число вершин ограничено 12, число рёбер — 40. Эта реализация предназначена для маленьких учебных графов, а не для больших сетей.

`graph-file.js` определяет версионированный JSON-формат: format=graph-classroom, version=1. Данные нормализуются до разрешённых полей, валидируются перед применением; размер импорта ограничен 32 КБ. 3D-ракурс и пользовательские XYZ не сериализуются.

`guide.js` хранит стартовый маршрут и словарь, `school.css` — актуальную тему 0.4. Основные стили остались в styles.css для сохранения совместимости экранов. Python-черновики записываются через 400 мс после ввода; при смене маршрута/вкладки и beforeunload запись выполняется сразу. Таймер очищается перед немедленным сохранением.

## Изменения 0.4

course-view.js формирует карту курса из переданных уроков, прогресса и последнего занятия. Выбор продолжения — отдельная чистая функция chooseNextLesson(). Остальные экраны пока остаются в app.js; дальнейшая декомпозиция описана в аудите.

static-files.mjs обслуживает только публичные файлы: кэш содержимого по времени изменения и размеру, gzip, отдельный ETag для сжатого и исходного ответа, условные запросы 304. Публичные ресурсы требуют повторной валидации. Пользовательские API-ответы сохраняют Cache-Control: no-store.

Учитель получает результаты только по занятиям, назначенным выбранному классу. Комментарии к неназначенному уроку запрещены. Работа остаётся общей для пары «ученик/урок», поэтому два учителя с одинаковым назначенным уроком видят одну отправку. Для независимых заданий нужна новая модель назначения и версий работ.

Черновики ответов в localStorage имеют ключ graph-practice-{userId|guest}-{lessonId}; последнее занятие — graph-last-lesson-{userId|guest}. Между устройствами синхронизируются отправленные серверу попытки, но не локальные незавершённые ответы. Удаление аккаунта очищает его локальные ключи на текущем устройстве.

Результат асинхронного запроса отображается только в соответствующем маршруте/уроке/классе. Смена шаблона Python отменяет активный запуск и очищает его старый результат. Обработчик ссылки к содержимому переносит фокус без изменения hash-маршрута.

## Миссия BFS, 0.5

mission-core.js — чистые createMission, applyMissionAction, restoreMission и missionHint. Графы и определения миссии неизменяемы. Движок проверяет очередь FIFO, сортировку новых соседей, отсутствие повторов, завершение обработки и оптимальность маршрута. Ответ содержит смысловой код обратной связи и параметры без текста интерфейса.

mission.js содержит контроллер DOM, нормализацию записи, экспорт отчёта и карточку входа. Каждый обработчик ограничен корневым элементом; dispose снимает обработчики через AbortController при смене маршрута, языка или аккаунта. mission-i18n.js — смысловые RU/KK-ключи с именованными параметрами; mission.css — стили миссии.

Ключ graph-mission-{userId|guest}-bfs-v1 в localStorage хранит журналы двух этапов, текущий экран, черновики маршрутов и объяснение. При восстановлении состояние BFS, ошибки и подсказки пересчитываются replay. Журнал ограничен 1000 действиями на этап; несовместимые версии и повреждённые записи отклоняются с уведомлением. Существующая серверная схема не менялась.

Это недоверенные локальные результаты. Пользователь может изменить журнал, число ошибок объяснения или признак его завершения в своём браузере; формат не применяется для аттестации. Сброс начинает новую попытку без встроенной истории; сохранить предыдущую можно экспортом. Выгрузка профиля включает локальную миссию, удаление текущих пользовательских/гостевых черновиков очищает соответствующий ключ.

Задания миссии используют собственные фиксированные графы и не зависят от редактора обычной лаборатории. Во второй сети старт 4, цель 7; принимаются, например, 4–2–1–7, 4–5–3–7 и 4–6–8–7. Пользователь видит разные связи, а не только переставленные координаты.

## Изменения интерфейса и устойчивости, 0.6

school.css содержит единые размеры, цветовые роли и адаптивные правила; mission.css — специфику миссии. icons.js предоставляет локальные декоративные SVG. course-view.js остаётся чистым генератором представления без доступа к DOM.

storage-state.js нормализует progress, ответы и черновики без изменения исходных записей. Адаптер storage хранит временную копию в памяти при отказе localStorage и сообщает об ошибке сохранения. Контекст запросов (пользователь, маршрут, класс) предотвращает применение запоздалых ответов к другому экрану. Это не заменяет серверный контроль доступа и не решает конкуренцию нескольких вкладок.
