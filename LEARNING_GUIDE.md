В самой платформе появился раздел **«С чего начать»**: там краткий маршрут, ссылки на подходящие занятия и словарь. Этот файл — более подробный план для тебя как автора диплома.

## 1. Графы на бытовых примерах

Представь район: дом, школа, магазин, парк. Это **вершины**. Прямые дороги между ними — **рёбра**. Все точки и дороги вместе — **граф**.

Изучи:

- вершина, ребро, сосед, путь, цикл, степень вершины;
- ориентированный граф: стрелка разрешает переход только в свою сторону;
- связный и несвязный граф: можно ли вообще добраться из одной части в другую;
- вес ребра: например, сколько минут занимает одна дорога;
- список смежности: запись соседей каждой вершины. Позже сравни его с матрицей смежности.

**Очень важное различие:** близость кружков на экране не означает короткий путь. Между близкими кружками может не быть ребра. Длинная нарисованная линия может иметь вес 1, а короткая — 9. Положение точек нужно для удобства рисунка; алгоритм читает связи и веса. В 3D действует то же правило.

**Сделай сам:** нарисуй 5 мест и 6 дорог. Найди соседей одной точки, посчитай её степень, укажи два пути между домом и школой. Затем сотри одну дорогу и проверь, все ли места остались достижимыми.

**В платформе:** занятия 17–18. Сначала исследуй 2D, затем поверни тот же граф в 3D. Список соседей должен остаться прежним.

**Можно идти дальше, если:** ты без подсказки объясняешь, что означает каждая точка, линия, стрелка и подпись веса.

## 2. Минимум Python

Нужно уверенно понимать: переменные, числа, условия `if`, циклы `for` и `while`, списки, словари, множества `set`, функции, аргументы и `return`. Для BFS понадобится `collections.deque`. Перед DFS изучи рекурсию и условие остановки.

Пример записи графа:

```python
graph = {
    1: [2, 3],
    2: [1],
    3: [1]
}

for neighbor in graph[1]:
    print(neighbor)
```

Здесь `graph[1]` — список соседей точки 1. Цикл выведет 2 и 3. У неориентированного графа связь записана с обеих сторон: если у 1 есть сосед 2, то у 2 есть сосед 1.

**Сделай сам:** добавь вершину 4 и ребро между 2 и 4. Напиши функцию, возвращающую число соседей указанной вершины.

**Можно идти дальше, если:** ты объясняешь каждую строку этого примера и самостоятельно меняешь его. Классы, декораторы и сложные библиотеки пока не нужны.

## 3. BFS — обход по уровням

Представь очередь в магазине: кто пришёл раньше, того обслуживают раньше. BFS работает так же с найденными вершинами.

1. Положили старт в очередь и отметили, что уже обнаружили его.
2. Взяли первую вершину.
3. Проверили её соседей. Тех, кого ещё не обнаруживали, добавили в конец очереди и сразу отметили.
4. Повторяем, пока очередь не пуста.

Сначала алгоритм доберётся до вершин в одном переходе от старта, потом в двух, потом в трёх. Он ищет ближайшие **по числу переходов**, а не по расположению на картинке.

**Сделай сам:** в занятии 19 перед каждым нажатием «Шаг вперёд» запиши очередь на бумаге. В занятии 21 прочитай пример Python, затем попробуй написать его по памяти.

**Нужно уметь объяснить:** почему открытые вершины отмечаем сразу при добавлении в очередь и почему цикл в графе не должен приводить к бесконечному обходу.

## 4. DFS — углубиться, потом вернуться

Представь исследование лабиринта: идёшь по одному коридору, пока можешь, затем возвращаешься к последней развилке. DFS обходит граф похожим образом.

Для рекурсивного DFS разберись со **стеком вызовов**. Он похож на стопку книг: последнюю положили — первой забрали. Функция вызывает себя для соседа, а после завершения этого вызова продолжает предыдущую работу.

**Сделай сам:** открой занятие 23. Перед каждым шагом назови, какой вызов лежит на вершине стека и куда алгоритм вернётся. Затем перейди к коду занятия 24.

**Можно идти дальше, если:** ты отличаешь возвращение из функции от перехода по новому ребру и понимаешь, почему DFS не гарантирует кратчайший путь.

## 5. Пути, веса и сравнение алгоритмов

Различай две задачи:

| Что минимизируем | Подход |
|---|---|
| Число переходов | BFS |
| Сумму неотрицательных весов | Например, Дейкстра |

Два перехода по 9 минут — 18 минут. Три перехода по 1 минуте — 3 минуты. Второй маршрут имеет больше рёбер, но меньшую стоимость.

Изучи **предшественника**: для каждой вершины запоминаем, откуда в неё пришли. Из цели идём по этим записям назад к старту, а затем разворачиваем список — получаем маршрут.

В Дейкстре нужно понимать две операции: выбрать незавершённую вершину с минимальным известным расстоянием и попробовать улучшить расстояния через неё. Дейкстра — дополнительный материал нашего курса, не обязательная основа всех занятий о путях.

После этого изучи сложность BFS и DFS `O(V + E)` при списках соседей. `V` — количество вершин, `E` — количество рёбер. Скорость анимации и количество экранных шагов не являются измерением времени работы алгоритма. Наш учебный проигрыватель хранит копии состояний для возврата назад, поэтому расходует больше памяти, чем один обычный запуск обхода.

**Сделай сам:** сравни два маршрута в занятии 28; в занятии 30 объясни, какую задачу решает BFS, а какую удобно решать DFS.

## 6. Как устроена наша программа

Для понимания текущей версии изучай **HTML → CSS → JavaScript → HTTP → Node.js → SQL/SQLite**.

| Часть | Простыми словами | Где посмотреть |
|---|---|---|
| HTML | Какие элементы есть на странице | `public/index.html` |
| CSS | Цвета, размеры, расположение | `public/styles.css`, `public/school.css` |
| JavaScript | Реакции на кнопки и обновление экрана | `public/app.js` |
| Модель алгоритма | Считает последовательность шагов | `public/core.js`, функция `trace()` |
| Содержание курса | Тексты, вопросы и примеры Python | `public/course.js` |
| 3D-геометрия | Поворачивает XYZ и переводит их в координаты экрана | `public/spatial.js` |
| 3D-рисунок | Показывает граф и готовый шаг | `public/graph3d.js` |
| Сервер | Проверяет вход, права и запросы | `server.mjs` |
| База данных | Помнит аккаунты, классы и работы | SQLite в `.local/` |

**Главный пример для защиты:** при нажатии «Шаг вперёд» мы берём следующий готовый снимок. Модель алгоритма не знает, нарисуют его в 2D или 3D. Рисунок получает текущее состояние и меняет цвета. Поэтому кнопку «Назад» можно реализовать без обратного вычисления алгоритма.

Для JavaScript изучи массивы, объекты, функции, модули `import/export`, обработчики событий, DOM, `async/await`, `fetch`, JSON и обработку ошибок. Для сервера — запрос/ответ, cookie, сессию, проверку прав и SQL-запросы.

**Не перепутай языки:** JavaScript реализует платформу. Python — язык, на котором ученик учится писать алгоритмы. Его программа исполняется в браузере через Pyodide. Проигрыватель заранее подготовленных шагов пока не показывает построчное выполнение произвольного ученического кода.

**Сделай сам:** найди `trace()` и `drawSimulation()`. Измени одну учебную фразу в `course.js`. Убедись, что поменялся текст, а ответы алгоритма остались прежними.

Unity/C# сейчас не требуется для понимания этой версии. Если вместе с руководительницей выберете Unity, тот же принцип разделения модели и отрисовки можно перенести в C#.

## 7. Аккаунты, данные и тестирование

Выучи разницу между **аутентификацией** («кто вошёл?») и **авторизацией** («что этому человеку разрешено?»). Например, ученик не должен получить работы другого ученика простой заменой номера в запросе.

Разберись, чем отличается хеш пароля от хранения пароля открытым текстом, для чего нужны сессии, резервные копии и серверная проверка входных данных. Читай `ARCHITECTURE.md` вместе с кодом, а не учи термины отдельно.

Изучи Git: репозиторий, `commit`, ветка, `diff`, `.gitignore`, возврат к предыдущей версии. В закрытый GitHub отправляют исходники и документацию. `.local/` с аккаунтами и работами туда не отправляют.

Для тестирования начни с простых вопросов: что случится с несвязным графом? Если старт совпадает с целью? Если файл повреждён? Если Python зациклился? Если ученик пытается открыть кабинет учителя?

**Сделай сам:** пройди сценарии из `TESTING.md`, каждый раз записывая ожидаемый и фактический результат.

## 8. Что делает эту работу дипломом

Важен ответ на вопрос: **какую трудность ученика решает каждый инструмент?**

- Очередь на экране помогает увидеть порядок обработки BFS.
- Стек помогает объяснить рекурсию и возвраты DFS.
- Предсказание следующего шага показывает, понимает ли ученик правило.
- Кнопка «Назад» позволяет разобрать место ошибки.
- Проверка Python связывает понимание схемы с самостоятельной программой.
- 3D позволяет рассмотреть связи под другим углом; пользу нужно проверить, потому что вершины и подписи могут перекрывать друг друга.

С руководительницей определите, какие задания проверяют каждую учебную цель. Для начала сравните понимание на двух похожих графах до и после занятия. Записывайте ошибки, самостоятельность решения и объяснения ученика. Маленькая проба с несколькими людьми даёт обратную связь об удобстве, но сама по себе не доказывает эффективность для всех школьников.
